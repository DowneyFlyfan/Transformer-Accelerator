# Shared five-cluster fabric implementation plan

Goal: share exactly five original four-core clusters between full selected-row projection and broadcast sparse down-projection, preserving retained down slots across projections. This is a local scheduling/protocol choice derived from the paper architecture, not a claim that unpublished scheduling details have been recovered.

Architecture: use five qualified shared_cluster_executor83 controllers, each connected to one original compiled-memory cluster. Projection distributes at most160 selected channel IDs in five32-row slices. Down mode broadcasts at most32 selected original IDs/codes to active clusters and assigns each a different32-output row group. Down output count1..160 determines the active cluster mask; never launch an invalid zero-output child. The producer supplies the output round start, slot1..15, append and final flags. A later complete-frame scheduler must loop thirteen output rounds for2048 hidden outputs, plus gate/up subgroups, and assert final only for the last contribution.

One round-robin external memory port locks advertised requests under backpressure and routes each accepted response to its owner. A fatal child/metadata/configuration error blocks new offers, drains the advertised/accepted external work, asserts one registered global reset for two cycles, invalidates every cluster context, then exposes an error result. Successful mode changes preserve contexts. Input readiness waits for all reset roots and child readiness. Results remain stable under backpressure. Exactly one bounded160-word result packet; no extra compute core or full5632-value cache.

Interface extends the existing160-row projection interface with in_is_down, in_accumulate,32 input codes, dense down stride, output start/count, shift and slot; output includes captured mode/start/slot. Projection errors clear channels/data/count and force last; down results clear channel/fallback fields. All producer fields are captured before they can change.
