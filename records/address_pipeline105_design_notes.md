# Address-generation timing investigation

The repaired original prediction parent now has independently verified original cores, reset ancestry and macro poses. Full-model slow setup remains -13.394268 ns, typical setup -10.458878 ns and fast hold -0.058541 ns. This does not meet the target1.72414 ns period. Evidence: recovered104_physical_diagnostic_qualification.json and the restored103 corner worst-path reports.

The worst slow/typical path starts at transfer/row_index_reg[3] and ends at req_address_reg[41]/SE. The source sparse_weight_dma selects one16-bit original ID from512 bits, multiplies it by the10-bit feature-strip count, adds the start strip, shifts to byte addressing, adds a64-bit base and checks the burst end before allowing the address register to update. The mapped path includes a Wallace multiplier network and many electrical-repair repeaters. Its delay is a hardware-path problem; rerunning synthesis unchanged or buying more processors does not remove that combinational dependency.

Next candidate should be a separately named pipelined DMA module, preserving the existing transaction interface and the frozen original source revision. Preserve sparse row writes, bank identity, exact burst lengths, early/late LAST draining, reset and error completion. Additional setup cycles are a local implementation choice, not a claim about the paper's undisclosed timing.
